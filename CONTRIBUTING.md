# Contributing to FlockLake

Thanks for your interest. FlockLake is a young project; the plan is in [ROADMAP.md](ROADMAP.md),
and every roadmap item is a GitHub issue titled with its ID (for example `M3.4 Budget planner v1`).

## Set up

You need [uv](https://docs.astral.sh/uv/) and [just](https://just.systems/)
(`uv tool install rust-just` works).

```sh
git clone https://github.com/soheil-mp/flocklake.git
cd flocklake
just bootstrap   # packages and dev tools from uv.lock, plus the git hooks
just check       # lint, format, strict types, secret scan, tests: the same as CI
```

## Make a change

1. Pick an open issue, or open one first for anything not on the roadmap. Say on the issue that
   you are working on it.
2. Create a branch from `main`.
3. Keep changes small and focused: one roadmap item per pull request is ideal.
4. Commit with [Conventional Commits](https://www.conventionalcommits.org/) messages
   (`feat(core): ...`, `fix(ingest): ...`, `docs: ...`, `test: ...`, `ci: ...`, `build: ...`).
   The changelog is generated from them.
5. Open a pull request. Use `Closes #N` for the issue, tick the item in ROADMAP.md, and fill in
   the template checklist.

Pull requests are merged with merge commits; history on `main` is never rewritten.

## Standards

- **Tests:** new behaviour comes with tests at the right level (`unit`, `integration`, `e2e`
  markers). `flocklake-core` keeps at least 90 % branch coverage. Prefer property-based tests
  (Hypothesis) for physics and conversions.
- **Types and style:** `mypy --strict` and ruff pass; public functions have NumPy-style
  docstrings with units for every physical quantity.
- **Decisions:** a choice with real alternatives gets an ADR in [docs/adr](docs/adr/).
- **Configuration:** read from environment variables; add each new variable to `.env.example`
  with a placeholder value. Never commit secrets.
- **Dependencies:** only add packages under permissive licences (MIT, BSD, Apache-2.0, ISC,
  MPL-2.0, PSF), and explain why in the pull request.

## Data and science

- Only open data that is not about people. Respect each source's licence and attribution
  ([data sources](docs/research/data-sources.md)).
- Test fixtures are synthetic and generated by code. Do not commit radar files or downloaded data;
  the `.gitignore` blocks the common formats.
- Processing stays physics-based and rule-based: every number must trace to a formula and a
  documented threshold ([ADR 0003](docs/adr/0003-physics-based-processing.md)).
- Respect the storage budget: never write code that bulk-downloads radar archives.

## Reporting problems

- Bugs and ideas: open an issue using the templates.
- Security issues: see [SECURITY.md](SECURITY.md); please do not open a public issue.
- Conduct: this project follows the [Code of Conduct](CODE_OF_CONDUCT.md).
